# 为什么这么设计 / Design Decisions

> 每一条都是真实的取舍：背景 → 候选方案 → 我们的选择 → 为什么。面试时欢迎顺着任何一条往下问。

---

## 1. 错题重做 → 「暗影复仇」：把间隔重复包进叙事

**问题**：题库产品的死穴是"错题本没人回头看"。传统错题本是一个列表，列表=负担，用户心理上是"我欠的债"。

**候选**：a) 传统错题本列表；b) 定时推送提醒（需要后端+通知权限）；c) 错题作为敌人回到游戏里。

**选择**：c。答错的题化为**暗影**，3 层后回到塔中重考，**连对两次**才净化，跨局生效——即使关掉浏览器，你的暗影还在塔里等你。

**为什么**：间隔重复（spaced repetition）的核心是"在快忘记时重见"。把重见的时机交给爬塔进度，把"连对两次"设计成巩固窗口，记忆科学就穿上了复仇剧的皮。用户不再"还债"，而是"复仇"——同一个行为，动机完全相反。

## 2. 零依赖：纯原生 JS，无框架、无构建、无后端

**问题**：求职备考工具的用户在图书馆/地铁/宿舍，网络不定；维护者只有一个人。

**候选**：a) React/Vue + 构建链 + 云端；b) 轻框架 CDN 引入；c) 零依赖原生。

**选择**：c。动画手写（`requestAnimationFrame`），音效用 WebAudio 现场合成（92 BPM BGM 不是一个音频文件，是代码），持久化用 localStorage + Service Worker 离线缓存。

**为什么**：零依赖=零供应链风险、零构建故障、完全可审计（题库 JS 文件可直接阅读）；GitHub Pages 免费托管，无服务器成本；断网可玩对备考场景是刚需。代价是动画/组件全手写——但对游戏而言，这些手写代码本身就是产品的一部分。

---

## 3. 存档码而不是账号系统

**问题**：跨设备续玩需要身份体系吗？

**候选**：a) 注册/登录（邮箱或微信）+ 云存档；b) 本地存档 + 手动存档码；c) 只做本地。

**选择**：b。存档（进度/暗影/成就/植物/解锁状态）打包成一段**存档码**（base64），用户复制粘贴即可跨设备迁移。

**为什么**：账号系统=服务器+密码安全+隐私合规+运维，对单机学习工具是过度设计；存档码零成本、零隐私风险、用户完全拥有自己的数据。产品哲学：**能不给用户注册的，就别让用户注册**。

## 4. 每题一句话解析 → 四选项逐一判词

**问题**：刷题产品的"看了解析还是不懂为什么错的不是我"。

**候选**：a) 只给答案；b) 答案+正确项解析；c) 每个选项一句判词。

**选择**：c（v0.3 从 b 升级）。错误选项的判词专门点破"这个选项在什么情境下是对的、这里为什么错"。

**为什么**：选择题的干扰项本身就是教学素材——用户蒙对时也能从错误项判词里学到东西；即时反馈（immediate feedback）是练习效果的最大杠杆之一。成本是题库编写工作量 ×4，但这是产品核心价值所在，值得。

## 5. 六爻求签：玄学的仪式感，工程的确定性

**问题**：想要一个"每日回来一下"的轻仪式，但随机签到没有灵气，真随机还会"今天比昨天签差"引发流失。

**候选**：a) 随机签到+奖励；b) 星座运势文案；c) 真六爻规则+确定性派签。

**选择**：c。同一个名字+日期+时辰**永远摇出同一签**（可复现、可解释）；1080 签池按日期做旋转派发，数学上保证**任意 90 天窗口内同一个人不会重签**；完整实现本卦/之卦/动爻（京房纳甲简化版），纯 JS SHA-256 驱动。

**为什么**：确定性派签让"玄学"变得可解释——用户甲和用户乙同日同学名才同签，这是缘分不是 bug；90 天不重签靠的是旋转构造而不是去重缓存，没有状态、无需存储。仪式感负责情绪价值，确定性负责工程尊严。

## 6. 年鉴风反馈墙：让用户敢说真话

**问题**：独立产品收不到反馈——反馈入口像"投诉"，用户不好意思用。

**候选**：a) 问卷表单；b) GitHub Issues；c) 美高年鉴/拼贴风的留言墙。

**选择**：c。几何 SVG 头像生成器（8 种随机组合，不上传真实照片）、匿名开关、贴纸感卡片、示范留言里专门有"如何报告 bug"。随喜支持会自动变成金色"感谢墙"卡片。

**为什么**：年鉴的氛围是"同学录"而不是"客服工单"；匿名+生成的头像把表达成本和社交压力同时降为零。设计目标只有一个：听到真话，尤其是坏消息。

## 7. 伴学植物：跨游戏的时间资产

**问题**：两个游戏像两个产品，用户玩一个就忘另一个。

**选择**：三盆植物（文竹/风铃草/星语藤）共享一份**学习时长账本**（`shared/plant-core.js`）：RPG 里学的每一分钟，试炼塔里的植物也在长；解锁条件挂成就（通关 RPG 才能养第三盆）。试炼塔左下角常驻迷你花盆。

**为什么**：把"总学习时长"这个冷数字变成活的、跨世界延续的生命——它记得你所有的付出。跨游戏资产让两个游戏互为留存钩子，而不是互相分流。

---

## 8. 进阶内容的零后端解锁：密文分发 + 本地哈希校验

**问题**：90 道进阶题需要按需解锁，但没有服务器、没有支付系统，也不想要。

**选择**：题库加密后**随前端公开分发**（`tower/js/deck-paid.js`，纯密文）；兑换码校验用 FNV-1a 哈希表（码不可反推），解密密钥按码逐个封装（SHA-256 链式密钥流 XOR），全过程本地完成。Web 与小程序共享同一套纯 JS 加密实现（`shared/paid-crypto.js`）。

**为什么**：不需要账号、不需要服务器、不需要数据库——一份静态托管同时服务两端。安全性建立在"哈希不可逆 + 密钥按码封装"上，smoke 测试持续验证"密文不含明文、跨塔码拒绝、伪码无效"。基础 245 题永远免费，进阶内容只是"愿意支持的开发者解锁"，不设任何功能绑架。

## 9. 贡献榜：不给名次，只给光

**问题**：排行榜天然让 90% 的用户变成"失败者"。

**选择**：贡献榜不给名次——贡献值（刷题/净化暗影/连胜）点亮塔层视觉，附 9 位虚构"示范塔友"垫底；你只和昨天的自己比。

**为什么**：学习产品的激励要避免零和。排行榜激励头部 5%，劝退长尾 95%；点亮+自我对比让每一分努力都有可见回报。3.0 版把用户自己（本地头像+昵称）也放上榜——那是"你的"墙。

---

## 10. 一个宇宙，两种玩法：理解力 × 记忆力

**问题**：AI 产品岗笔试考两类能力——判断力（情境决策）和记忆力（概念辨析），单一形态只能练一种。

**选择**：RPG 练判断力（十周剧情，每个决策写进指标），塔练记忆力（345 题爬塔+间隔重复），用**术语表互通**（RPG 里点术语直跳塔里对应题）、共享存档码、共享成就、共享植物时间账本，把两个游戏缝成一个宇宙。

**为什么**：RPG 里"理解"的知识，到塔里"记牢"；塔里记的概念，回 RPG 里"用对"。理解与记忆互为上下游，两个游戏互为复利——这也是产品名里 "Exam Prep **Games**" 用复数的原因。
